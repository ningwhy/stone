### 朝向测法：未走 identity 管线的新角色

这三人没走 `identity` 管线，官方裁切读不到脸。流程：

1. `scripts/inspect_face_boxes.py` 自动检测脸框 →
2. `scripts/facing_wide_scan.py` 按脸框手工裁切头部、放大到 760–900px →
3. `scripts/facing_vision.swift` 读数（鼻尖与嘴中心相对两眼中点的水平偏移，
   **正号 = 朝右**，鼻与嘴必须同号才算有效读数）→
4. 读不出来的走 `scripts/build_facing.py` 的 `REVIEWED` 目视裁决表。

**标尺必须双向**——只用朝右样本无法区分「符号规则」与「巧合」。本轮用
4 个朝右（`baochai-chibi` / `daiyu-chibi` / `feng-chibi` / `baoyu-chibi`）
+ 8 个朝左，**11/12 命中**（唯一未命中 `jia_lian-portrait` 因 manifest 无 faceBox，
属缺样本）。

**被自己的标尺证伪的方法**：早先的「自动宽扫法」（不靠脸框、按高度比扫 7 个位置）
对 11 个标尺只出 6 个读数，且 2 个与已知答案相反（朝右读成 left、朝左读成 right）。
已废弃，改用手工脸框裁切。

**结果**：六个新资产朝向全部为 `right`。

- `cui_lv-chibi` 是目视裁决：检测器在 tight/wide/wider × 900/1400 六种组合下全部返回
  NONE。目视比对 `baochai-chibi`、`si_er-chibi`（均为朝右）——她的鼻尖与嘴基本落在
  两眼中点上，只有极轻微偏右，按「鼻嘴同号、正号朝右」记为朝右。

**`cui_lv-portrait` 的 faceBox 人工裁决**：自动检测把米白色围裙误判为肤色，
框到了腰腹（`[0,99,183,312]` 横跨半个身子）。真实脸块由**上部 30% 区域**内的
肤色连通块给出 `[55,23,115,108]`，目视核对后写入 `inspect_face_boxes.py` 的
`REVIEWED` 覆盖层。

### 句号索引切片（本回沿用第 20 回的方法论）

底本同形短句多（「我知道了」「说的是他」），字符串 `find` 会命中前一处、切到别人的字。
改按 `(?<=[。！？])` 切句（闭合引号归入前一句），用 `[s_from, s_to)` 唯一定位。

**单调性校验的三级比较**：同一句号区间常被拆成「叙述 + 台词」两个节点，
它们共享 `(段, 句)`，所以第三级用节点在 CUTS 里的次序打破平局；
只在**严格倒退**时报错（`pos[i][:2] > pos[i+1][:2]`），相等不算矛盾。

### 舞台连续性自检

引擎只在**换场景**时清空舞台（`src/engine.ts` 的 `enter()`），同一场景角色可见性保持；
「move 一个从没 show 过的人」会在读者点到那一步才抛 `[节点] 移动角色未显示`。
**只有 `move` 会在运行期抛错**——`effect` 只播特效，`hide` 对不在台上的角色是空操作。
生成期必须拦住。（本回首跑就靠这条抓出 `c21-xushi` 段全无 show/move → focus 为空。）

## 八、这一回带出的三处测试修正（**下一回照做**）

第 21 回一上线，就有三类「写死旧回次」的断言同时变红。它们都不是产品缺陷，
是**测试把自己的历史快照当成了不变量**。逐条记下来：

### 1. 封底不是「某一回的属性」，是「后面还有没有回」的属性

第 18/19/20 回的定向测试都断言封底显示「全书至此，砖石犹温。」——
那是它们当时恰是末回的结果。第 21 回上线后，第 20 回的封底变成「开启下一回 →
第二十一回」，三份测试一起红。

**修法**：抽出 `tests/lib/backcover.mjs`，判据与产品代码（`src/App.tsx` 的 `nextBook`、
`src/leaves.ts` 的 `chapterLeaf`）看**同一份数据**，断言的是「封底与下一回的有无相称」，
而不是「封底长什么样」。

### 2. 「终幕」标签只标在**全书**末节点上

`src/App.tsx`：`state.index===story.length-1 ? '终幕' : step.id`。
第 18 回不再是全书末回之后，它的末节点标签就是 `C18-135`，不是「终幕」。
第 18 回测试里那句 `assert.equal(label,'终幕')` 是过时的。

**修法**：`tests/lib/backcover.mjs` 的 `assertNodeLabel()`——判据是
「这个节点是不是**全书**的末节点」，用产品代码的 `story` 数组实读。
线上测试里那句 `waitForFunction(...==='终幕')` 同理改成等节点 id。

### 3. 「查无此人」的样本随回目推移而失效

`tests/browser-smoke.mjs` 用一个「在全部回目正文里一个字都没出现过」的名字
验「搜索不能凭空造出段落」。这个样本每加一回就会被推翻一次：
妙玉（18 回）→ 晴雯（19 回）→ 麝月（20 回）→ 紫鹃（21 回）。

**本回换成「檀云」**：她是宝玉房里的丫头，二十一回正文、`src/`、`design/` 里
一个字都没出现，也不在 cast 表里（搜人物是靠在场人物命中的，她压根没被画过）。

**判据要覆盖所有可搜路径**，只查正文是不够的——名字出现在地点、在场人物或段 id 里，
搜索照样能命中。`tests/toc.test.ts` 那条断言现在查正文、地点、在场人物、段 id 四路。

**另外两处同类过时断言**（同样在第 21 回上线后变红）：

- `tests/engine.test.ts` 写死 `story.at(-1)?.id === 'C15-091'` →
  改为「末节点属于最高的那一回」+「末节点自称的回数等于那一回」。
- `tests/toc.test.ts` 写死「宝钗只在前四、五、七、八回在台」→
  宝钗在第 18/19/20/21 回都有戏份，改为从数据实读她在哪几回在台。

## 九、顺手修掉的存量缺陷：bamboo-cluster 一直是坏的

`bamboo-cluster` 自 2026-10-29 首次提交起就是坏的——运行时位图的绿色像素只占 **0.1%**，
屏幕上是一块米色板，而不是一丛竹子。**13 张现存地图一直在摆它**。

根因：源图把竹子画在一张米色纸地上（生成 prompt 已要求「纯净纯白背景」，模型仍给了纸地），
SAM 抠图把纸底当成了背景的一部分保留下来。

修复路径：
1. ComfyUI 重绘（seed 10400571，prompt 明确「竹根悬空露白、无地面平台、纯白背景」）；
2. `scripts/cutout_white_backdrop.py`——边界洪泛抠图，与 `repair_matte_bamboo_gate.py` 同一手法；
3. `scripts/replace_bamboo_cluster.py` 接进 calibration → manifest → webp。

绿色像素占比 0.1% → 68%。旧源图保留在 `art/source/`，是替换不是删除。

**顺带发现**：服务端 SAM 管线当前不可用（BiRefNet 节点报
`'Config' object has no attribute 'is_encoder_decoder'`）。纯白背景的道具今后应直接走
`cutout_white_backdrop.py`，不必依赖 SAM。

**顺带修正**：重跑 `build_art_assets.py` 会重算全部资产 anchor。第 20 回新角色
（贾环、赵姨娘、湘云、麝月、贾琏、元春）的 calibration 只记了 `height` 没记 `width`，
旧 anchor 记的是**未裁切原图**坐标（如 `jia_huan-chibi` anchor=[443,947]，而位图只有 66×116），
运行时 `setOrigin(anchor/w, anchor/h)` 会把精灵放到画面外。重跑后 8 人全部修正到脚点
（偏差 0.1–1.1 px）。
