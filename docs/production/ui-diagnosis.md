# UI 改造的诊断纪律

> 适用范围：任何「不好看 / 不整齐 / 太丑 / 太小 / 不大气」类的界面反馈。
> 来源：册页卡片改造（`8df83d1`）与账簿卡片改造（`4b5b05a`）两轮实践。

## 一、核心心法

> **把审美问题翻译成可测量的数字。**
>
> 「太大气」「不整齐」→ 换成「卡面统一 288px」「每列缩略图 66px」「越界元素 0」
> 「同一网格内高度集合唯一」「贴图铺满卡面，误差 ≤2px」。
>
> 审美是主观的，数字是客观的。凡是能写成断言的，就别靠吵架解决。

反馈里「丑」永远是入口，不是结论。本文档规定如何从「丑」走到「改哪一行」。

## 二、五步闭环

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| 1 取证 | 截图目检，找出「哪里看着不对」 | 一串待验证的怀疑项，**不是**结论 |
| 2 实测 | `getBoundingClientRect` / `getComputedStyle` 量真实数字 | 数字，用它推翻或确认怀疑项 |
| 3 定位 | 找根因：谁渲染的、什么结构、谁在继承 | 一条具体的因果链 |
| 4 改 | 最小改动，优先加限定而非改基类 | 改动点 + 理由注释 |
| 5 验证 | 自动化断言防回归 + 人工目检管好不好看 | 两份证据都要有 |

数字没对上就回到第 2 步，不要在第 4 步上打补丁。

## 三、视觉判断不可靠，DOM 才是权威

这是本项目付出最多代价的一条。实测中视觉模型至少四次给出错误结论：

| 视觉判断 | DOM 实测真相 | 若轻信会怎样 |
| --- | --- | --- |
| 「卡片高度参差不齐」 | 全部 138px，完全等高 | 去改一个本来没问题的地方 |
| 「所有贴图都没加载」 | 视口内 8 张已加载，其余是懒加载占位符 | 破坏懒加载机制 |
| 「有张小人立绘溢出卡片」 | `position:static`、图片 54×66 完整填框、越界元素 0 | 白查一轮，浪费一轮改动 |
| 「账上 0/n 笔都没解锁」 | 实际 n/n 已解锁 | 重做解锁逻辑 |

视觉模型还会读错中文（把「赚 102 两」读成「银asd 102 两」）、把花押字块当成虚线空框。

**规则**：

- 截图目检**只用来发现问题**（「这里看着不对」），不用来下结论。
- 任何「没对齐 / 溢出 / 没加载 / 尺寸不对」的判断，必须用 DOM 数字确认后才能进代码。
- 报告问题时同时给出数字：宽度、高度、位置差、集合去重后的取值。

## 四、改全局样式前先查影响面

册页改造时加了这条：

```css
.card-thumb { position: absolute; inset: 0 }   /* 为了让图铺满卡面 */
```

`.card-thumb` 同时被册页卡片和账簿卡片使用。改基类时只想着册页，结果账簿的立绘卡全部 `absolute` 飞出按钮（实测 `left` 分别为 −25 / −251 / −476），行内货品图一并受害。

**规则**：

- 改任何 `.xxx` 全局规则前，先 `grep -rn "\.xxx" src/` 把使用点全找出来。
- 影响面不明确时，用**加限定**（`.card-thumb.ledger{position:static}`）而不是改基类。
- 已有 CSS 经多轮修订，规则尾部常出现「无穷覆盖」；新增规则优先整理进对应区块，不在文末继续堆。

## 五、滚动容器与懒加载是绑死的

给 `.atlas-body` 加 `overflow:auto` 让它滚动 → 真正的滚动容器从 `dialog` 变成内层元素 → 卡片贴图的 `IntersectionObserver` 的 `root`（`dialog`）不再是滚动祖先 → `rootMargin` 失效 → **贴图永远停在占位符状态**。

看起来是「加个滚动」这种无害改动，实际打死了整个懒加载。

**规则**：

- 滚动容器是 DOM 结构属性，不是样式装饰。给任何元素加 `overflow` 前，先确认它不是某个 `IntersectionObserver` 的 `root` 或其祖先。
- 改完必须验证：视口外的贴图**仍然是**占位符、视口内的贴图**确实**加载了。两头都要查。

## 六、CSS 特异性：祖先的规则会偷走子元素的样式

```css
.atlas-body p, .atlas-body small { font-size: 12px }   /* 特异性 0,1,1 */
.bond-note { font-size: 10.5px }                        /* 特异性 0,1,0 → 输 */
```

结果卡里所有字都被统一成 12px，各卡自己定的字号根本没生效——这正是用户抱怨的「大的大小的小」的隐藏来源之一。

**规则**：

- 子元素要覆盖祖先的通用规则时，特异性必须相等或更高；用 `.card-face .bond-note{...}` 而不是靠源文件顺序。
- 不用 `!important` 掩盖问题。
- 改字号后**实测每个类的计算值**（`getComputedStyle(el).fontSize`），不要相信源码里写的数字——写的是 10.5px、实际算出来 12px 的情况真实发生过。

## 七、空态也是设计

账簿里 16 个人物有 5 个没立绘、22 件物品基本没图。旧做法是虚线空框 → 看着像没加载完。

改法：姓氏/物名首字的**朱印花押**，并按类别着色（银两金 / 衣物绯 / 物件赭 / 人朱 / 人情青）→ 变成「有意为之的账本暗记」。

**规则**：

- 缺资源优先用**设计语言**补（花押、印章、剪影、底纹），不要留空白框或虚线框。
- 空态要有克制的文案（「读到对应剧情后入册」），不要让用户以为出了故障。
- 缺图与有图的卡片**占位尺寸必须一致**，否则网格参差。

## 八、等高是纪律，不是巧合

用户抱怨「大的大小的小」，往往来自多个独立原因：

| 症状 | 实测根因 | 修法 |
| --- | --- | --- |
| 行高随字数变 | `.ledger-circ` 用 `min-height:2lh`，长文按自然高度溢出 | 改 `height:2lh` + 固定行高 |
| 竖排引文行高不齐 | 中间两行折行（实测 22/43/43/22） | `white-space:nowrap` 或固定行数 |
| 各卡字号不一生效 | 祖先规则特异性更高（见第六节） | 补同等特异度兜底 |
| 落款高低不齐 | 附注长短不一（41~72 字） | 落款区固定高度，或超出用行数限制 |

**规则**：

- 同一网格内，同类卡片的**外框尺寸必须唯一**。用「集合去重后长度 = 1」做断言。
- 内容长短不能改变外框尺寸。文字要折行就折行，但折行数固定。
- 浮层文字压在图上时，行数要按卡片类型分档，不要取折中值（信物卡四行引文需要 74% 墨色高度，地志卡一行只需 52%）。

## 九、测试断言要跟着结构改写

旧断言写的是「按类定高 token186/bond170/place150」「缩略图统一 140px」——新结构全不成立。留着不改，测试就是假绿。

**规则**：

- 结构变了，旧断言必须**改写成新不变量**（卡面统一高度、贴图铺满、越界元素 0），不是删掉了事。
- 线上复验脚本同样要改：`.bond-note` 移出卡面后线上复验直接失败——这是好事，它证明线上脚本真的在验东西。
- 断言要选**稳定判据**：`:has(.card-thumb)`（有画框即已配图）比 `:has(.card-art)`（要求图片已解码）稳，前者不受懒加载时序影响。

## 十、验证四层，缺一不可

| 层 | 命令 | 查什么 |
| --- | --- | --- |
| 单元 | `npm test` | 引擎、动作、美术、地理规则 |
| 内容 | `npm run check:content` | 节点/段落/地图/资产引用、账簿门禁 |
| 浏览器 | `node tests/browser-smoke.mjs` 等 | 真实 DOM 下的尺寸、命中、懒加载 |
| 线上 | `ORIGIN_DIRECT=1 TEST_URL=https://stone.yan.pub/ node tests/online-ledger.mjs` | 部署后的真实资源与样式 |

线上复验要带 `ORIGIN_DIRECT=1` 直连源站绕过 CF Bot 质询；新 profile 首次访问正式域名会 `ERR_TIMED_OUT`，需预热 profile 或删掉旧 profile 目录（内存里存着旧存档会导致场景 id 对不上）。

**规则**：

- 自动化断言防**回归**，人眼目检管**好不好看**。两者都要有，不能互相替代。
- 临时调试脚本（`check2.mjs`、`debug-token.mjs` 一类）用完即删，不要混进正式测试目录。
- 提交信息写清**为什么**，尤其写清「哪个改动泄漏到了哪里」。半年后翻到这条 commit 的人会感谢你。

## 十一、本项目已知的连带风险

| 改动 | 连带风险 | 检查点 |
| --- | --- | --- |
| `.card-thumb` 定位 | 册页要 `absolute` 铺满，账簿要 `static` 正常流 | `.card-thumb.ledger{position:static}` |
| `.atlas-body` 加 `overflow` | 打死贴图懒加载 | 视口内外贴图都验证一遍 |
| 弹窗加宽 | 册页要 1000px 摊画，账簿要 720px 才不碎 | 账本用独立 `is-ledger` 宽度 |
| `.card-face` 通用文字规则 | 压过卡内各类字号 | 改后实测每个类的计算字号 |
| `object-fit` 覆盖 | `cover` 裁掉竖版立绘的脸 | 人物用 `contain` + 贴框顶；器物用 `cover` |

## 十二、一句话总结

> 截图找问题，数字定问题，改动解问题，断言防问题，人眼管审美。
>
> 五步之间任何一步跳过，后面都要花两倍代价补回来。
