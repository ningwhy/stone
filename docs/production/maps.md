# 地图构建、方位与准确放置

## 先定叙事关系，再做地图

每张局部舞台 40×40，tilewidth=128、tileheight=64，orientation=isometric。全府总览也用 40×40，但它与局部舞台不是同一物理比例。先列本场地实际地点、入门顺序、可行走区域、阻挡、讲话站位与进出门，再摆建筑；不要先铺满资产再让剧情穿墙。

列 c 增加为东，行 r 增加为南：北在屏幕右上、东右下、南左下、西左上。方向/门向使用世界方位说明，不能用“图像在最下方所以是南门”。沿用 [空间考据](../estate-geography.md) 的既定关系。

## TMJ 契约

根属性 `sceneId` 唯一，另外有 title/theme；40×40 普通等距地图放 `maps/` 顶层自动加载。可选的根属性 `water`（字符串 `"col,row,w,h;…"`，river 主题的水带矩形列表）与 `flowerbeds`（bool，是否画默认花坛，缺省 `true`）只影响地板表现，不改变可走集合：写了 `water` 的 river 舞台按矩形画水面与波纹，取代旧版固定水塘；`flowerbeds=false` 的舞台（如运河纤道）不画花坛。两者都不写时保持旧外观。必要的对象层如下，大小写不可变：

| 层 | 运行作用 |
| --- | --- |
| `PlanZones` | 原型地面区域；A/A数字/B/C/D/E/F ID 的区域纳入可走集合 |
| `PlanBlockers` | 从可走集合中减去矩形障碍 |
| `Anchors` | 命名格心，剧情 focus / show.at / move.via 引用它 |
| `Routes` | 每项属性 route_id、逗号分隔的 anchor_ids；帮助生成通行走廊 |
| `Art`（可选） | 图像对象，属性 asset 指 manifest ID；width/height 为最终显示像素尺寸 |
| `ArtFootprints`（可选） | 独立矩形碰撞，Art 图像不会自动变碰撞 |
| `Labels`（可选） | 格心标签，name 为显示文本 |

Anchors 在 Tiled **对象坐标**里：`x=(c+0.5)×64`、`y=(r+0.5)×64`。例如格 (10,12) 为 (672,800)。矩形区域/障碍为 `x=c×64,y=r×64,width=w×64,height=h×64`。不是把屏幕菱形坐标直接填进点对象。

读取器以对象真实 x/y 为准，旧 col/row 属性只是备注。所有锚点落格心、在界内、不同名称不重复。必需层即使空也保留。Zones 的 ID 取名称第一个空格前的部分，使用如 `A0 前院`；不要用任意名字后期待自动变可走。

Route 折线是 Tiled 示意；运行器消费 `anchor_ids`，先沿列再沿行补走廊，再减障碍。不要把所有锚点随手拼成长路线，否则会造出不该有的捷径。路线应按合法通道分别列出；窄门两侧加途经点。实际 A* 是四邻格，不切斜角。每个 show 点与 move 起终点可通行，所有必要途经点应可达。

## 逻辑格到画面

人物脚下格心屏幕坐标：

```text
Gx = (c-r) × 64
Gy = (c+r+1) × 32
```

图像有像素锚点 A=(ax,ay)，比例 s；锚点是鞋底/树根/门槛/前门台阶，未必是包围盒底中点。Tiled 图像集合 `objectalignment=bottom`，对象图像底部中心 B：

```text
Bx = Gx + (imageWidth/2-ax) × s
By = Gy + (imageHeight-ay) × s
object.x = By + Bx/2
object.y = By - Bx/2
object.width = imageWidth × s
object.height = imageHeight × s
```

网页恢复 Bx=`object.x-object.y`、By=`(object.x+object.y)/2`，图像 origin=(.5,1)。人物 origin 则直接用 `(ax/width,ay/height)`。深度按脚下/门槛地面 y 加 depthOffset，不按屋顶或图像包围盒下缘。

门要先校准透明门洞和门槛位置，再设置两边的行走锚点及碰撞。禁止用挪剧情锚点掩盖鞋底/门槛测错的问题。镜像和剪切在资产校准阶段固定，Tiled 不能代替美术方向制作。

## Tiled 编辑支持范围

支持 Art 真实位置、显示宽高、asset、visibility、depthOffset，以及两个室内外自定义属性：`PlanZones` 对象的 `indoor`（bool，该地面属于建筑内部）与 Art 对象的 `interiorZone`（string，这栋 `visibility=exterior` 的外观盖住哪个室内地面）。`visibility=exterior` 不再只跟随剧本 roof 开关：只要有人站在 `interiorZone` 指向的室内地面上，这栋外观立即隐藏，露出室内地面与室内陈设；人走出来自动恢复。剧本 `roof` 动作仍是显式覆盖（`visible:false` 强制整场室内，`visible:true` 强制看外观）。当前不支持对象旋转、gid 翻转位、分组/层偏移、任意多边形碰撞，也不完整解释 layer opacity、普通地砖层碰撞。旋转/翻转已报错，其余缺失能力不会自动实现。编辑器用默认无偏移对象层、无旋转图像。

两个属性由 `scripts/annotate_interiors.py` 幂等写入已提交的 TMJ（`python3 scripts/annotate_interiors.py`）；新增院落或改室内范围时改脚本里的 `INDOOR_ZONES` / `INTERIOR_OF` 再重跑。室内陈设补齐用 `scripts/furnish_interiors.py`，放置格子先用 `scripts/story_path_cells.py` 确认没有被任何 move 路线占用，避免挡路。`scripts/render_map_preview.py` 可在不起服务的情况下近似渲染地板与 Art 布局，用于快速目检室内外效果。

## 室内家具批次摆位（2026-10）

`scripts/furniture_place.py` 用上面的 Bx/By 公式把 9 件新家具写进 11 张室内图，并把 8 处重复的 `tea-table` 换成更合场景的桌子（条案×3、书案×3、八仙桌×2）。计划表在脚本内，幂等：同资产同格的对象已存在就跳过；换装直接改原对象的 asset/gid/宽高并保持地面格不变，关联 ArtFootprints 同步改名。新增对象一律补 64×64 碰撞（与既有家具同约定），`nextobjectid` 取全图最大值递增。

选格规则：

- 家具地面格必须落在某个 `PlanZones` 内（脚本外由 `verify_furniture.py` 复核）。
- 座位（椅/凳）放在演员身后：该格的 `col+row` 不大于演员格，运行时先绘制，不会盖住人物；西—南向的"背对桌子"方向 col+row 不变，此时凳子与人物同深度并排，同样不遮挡。
- 大件（条案 195px、顶箱柜 130×222）要预演遮挡：按人物实际 Q 版尺寸逐anchor 估算覆盖率，超过脚部级的擦边就换格；既有场景本来就允许桌子盖住坐姿人物脚边（晚膳圆桌盖贾母约 25%），新家具不高于这个基线。
- 换装后不挪剧情锚点；`tea-table` 只留在情境需要处（晚膳斟茶、碧纱橱、王夫人茶座、刑堂密室），从 11 张减到 4 张。

`scripts/verify_furniture.py` 复核四件事：每个 Art 的 asset 在 manifest 内、地面格与 Footprints 都在房区内、没有 Art 画在演员前面却盖住演员盒（按剧情 show/move 取真实演员尺寸）、深度用 `artGround` 的地面 y 比较（同格时人物因 +1 在前）。改完跑 `npm test`（全节点 20 图寻路会暴露挡路）与 `node tests/interior-roof.mjs`。

打开 `maps/rongguo-entry.tmj` 或新局部图，保持相对 TSJ 路径和 asset 属性。移动 Art 后核对关联 Anchors；碰撞另改 ArtFootprints。保存刷新网页，先清理不兼容的测试存档或从段落起点重放。Tiled 中看起来对齐还须网页复核脚下锚点。

`build_art_assets.py` 会更新 TSJ 的全部 gid，校准清单顺序变化时需要重导出引用 gid 的地图。网页按 asset 名称读取，但 Tiled 按 gid，不能只让网页看起来对了。

## 台基 `terraces` 与成套摆放（2026-10）

等距下一格是 `(±64, ±32)` 像素，而一张案只有 146px 宽——把椅子放到「相邻一格」就等于把它甩到案外半张桌子的地方。**只按整数格摆小件家具，必然摆出「随手撒了一地」的效果**；这是第五回太虚幻境与第六回凤姐院返工的直接原因。

两条新契约：

- 根属性 `terraces`（字符串 `"col,row,w,h[,court|path];…"`）：石台矩形列表，仅影响地板表现。「court」是带台帮（前两个朝向镜头的面挤出 12px）的台基，dream/myth/ruins 主题不铺地、没有台基时家具与建筑全浮在空底色上；「path」是院里的甬路（石条色、逐格接缝、台帮 7px），用来给一片素平大方砖的院子拉出轴线。绘制顺序即列表顺序：**由北（远）到南（近）**，近的台帮才压得住远的台面；相邻两块各叠进对方一格，接缝就成了一道踏跺。台基在 PlanZones 铺装之后绘制，故 garden 主题的舞台也能用它铺甬路。
- Art 的 `visibility=interior`（配 `interiorZone`）：与 `exterior` 相反——屋顶盖着时隐藏、掀顶后显示。室内陈设必须用它，否则屋顶还在时自鸣钟、多宝阁会站在屋墙外的院子里。

成套摆放的做法：一处陈设先定一个落点（人站的锚点、炕沿、案心），其余件按**屏幕像素**相对它写，而不是各填一个格：

```text
dc = dx/128 + dy/64       dr = dy/64 - dx/128
```

两个构建脚本各有一个 `at(c, r, dx, dy)` 做这个换算（`scripts/build_chapter05.py`、`scripts/build_chapter06.py`）。四条经验：椅/凳贴案沿 `±(案宽/2+10)`，不是隔一格；瓶炉落在案面高度而不是案前地面；同类件用同一个 scale，只有成组（大橱一排、双树夹道）才允许整齐对称；对称只留给原著明写的「两边配殿」这类，其余故意错开高低远近。

## 院落语法：围墙、甬路、花圃与剖开的屋（2026-10）

这一批把「每个院子、每间屋都按原著摆设」落到实处，靠的不是再画一遍图，而是四条**舞台契约 + 两条构图经验**。起因是二十四张地图共用同一份布局：同样的四块 zone、一张 800px 整场景插画、三四个道具——所以每个地方看起来都一样，整场景插画还读成一顶扣在地上的迷你院落。

### 契约

| 属性 | 写法 | 作用 |
|---|---|---|
| `walls` | `"c1,r1,c2,r2;…"` | 院墙。画成 36px 高、带瓦顶压边与脚下投影的立面；**两段之间的缺口就是门**。原先 `entry`/`east` 在 MapScene 里硬编码的围墙已删除，改用这个属性。 |
| `flowerbeds` | `"c,r,w,h;…"` 或 `false` | 花圃改为**逐场景声明**。以前七块固定花圃会画进每一张 garden 图，连农家院也不例外。 |
| `water` | `"c,r,w,h;…"` | 任何主题都能画水。`ruins/myth/night/dream` 用墨黑水色（迷津的黑溪），其余用青绿水色。 |
| `indoor` + `interiorZone` | zone 第 5 项 `True`、第 6 项给 id；道具第 5 项写该 id | 屋顶与该屋陈设各自认领地面：**一图两屋时只掀走进的那一间**。 |
| 剖开的屋 | `MapScene.roomWalls` | 掀顶会连墙一起藏掉，房间只剩一片空地。现在按 `indoor` 地块补画三面墙脚（门那面留空），所以掀顶后仍是一间屋子。 |

### 两条构图经验

- **一屏约 12×9 格。** 镜头只装得下 1200×520px 左右，等距下一格是 128×64。两座门相距 16 格时，镜头对准街心就一座也看不见——宁荣街因此从 16 格收到 10 格。每条布局都以此为准：主体必须落在焦点锚点 ±6 格内。
- **房内地面要和屋顶同大。** 20×19 的地面配一座 1100px 正房，人就散在一片大空场上（晚膳、碧纱橱最初都是这样）。现在晚膳 `11×9`、碧纱橱 `10×8`、王夫人房 `13×9`，家具才围得起来。

## 荣府总览与跨院路线

`design/atlas-maps.json` 是舆图权威源：levels[].locations / gates / walls / groups / network.nodes|edges，外加 `sceneLevel`（场景 → 层级）。SVG 和 `build_world_map.py` 参考同份数据。Tiled 编辑不会回写。层级：realm（天下）→ capital（京城）→ rongguo / ningguo / daguanyuan（府内）。

当前西墙 c=4，西角门 (4,30)；南墙 r=36，正门 (23,36)，黑油门 (35,36)。去贾赦院经过西角门—府外道路—正门外—黑油门；回程按本版选择走正门。墙段在门洞留开口，网络边四邻轴向，检查只在门洞穿墙。新增院落同时改道路、墙、门、地点说明和测试，不能画一条直线越过建筑。

总览院落要用建筑外观；点击标签查看地点，点“从此处剧情开始”才 seek。透明屋顶整块包围盒不能覆盖邻院标签的可点击范围，标签最后绘制并提供可访问名称。外地或梦境场景用行迹目录，不勉强套进荣国府道路。

## 地图目检与边界

大地图、局部图、指北针和原文方位保持一致；看人物是否穿门、遮挡是否能读、墙是否留洞、动线是否真实可达。入室时 exterior 整楼隐藏由室内地面占位自动触发（见上文两个自定义属性），不是只靠剧本 roof 动作；当前没有精细前柱/屋顶遮挡系统。新增主题的地板/花坛/水面配置需在对应场景检查。不要以墙画在地板上而声称已自动阻挡。

修改生成器、校准资产前先看 [覆盖表](architecture.md)，保留手工编辑副本。Tiled 应用未实际打开过，就将其列为待验收，不能用 JSON 检查代替目视结论。

## 镜头预算：一张图要能看见它自己（2026-10 末）

这一轮返工的教训不是「素材摆错了」，而是**画得下不等于看得见**。镜头并不以锚点为中心：
`MapScene.target()` 把人物放在视口中心偏上 65 px，`fit()` 又把 zoom 夹在 0.9，于是 1440×900
的画布实际只露出约 1600×1000 世界像素，其中上方还要让给段落条、下方让给对话框——**锚点以上
约 430 px，以下约 340 px**。

按这个预算量下来，之前每张图至少犯了三样：

1. **屋顶立得比镜头高**。每个正殿都写 0.84–0.94，可 `main-hall` 原画 1100×888、`yamen-hall`
   只有 900×520：同样的系数，荣禧堂站 780 px，应天府只站 440 px。现在建筑按**高度**授权，
   `stage_defs.fit(asset, scale)` 以 `MAX_TALL` 为上限（正殿 430、配殿 360–400、院门 340），
   系数只是上限而非目标。
2. **屋顶站在屋子中央**。屋顶是掀在**前檐**上的，脚线必须压在所属地坪的**南沿**（`stage_defs.eave()`）。
   站在房间中间时，屋顶掀开后近半边屋子没有顶，山脊还高出画面 200–400 px——智通寺整场都没出现过，
   因为它的脚线在屋里、镜头里只剩空砖地。
3. **`-house`/`-temple`/`-room` 不算屋顶**。`is_shell()` 现在把甄宅、葫芦庙、智通寺、村肆、
   农舍、`ruined-house`、退步（`qin-room`）一并算作屋顶；此前它们被当成室内陈设，玩家站在院里时
   整座房子是隐形的。

配套的三件工具：

```bash
npm run map:framing                      # scripts/check_stage_framing.py：逐图逐件算「看得到吗」
python3 scripts/refit_stage_assets.py    # 手绘两张（c6_wangchui、rongguo-entry）按同一契约补课
```

`map:framing` 只从「这件东西真能看见的那些锚点」去判：外壳（`exterior`）只从地板**外面**的锚点算，
室内陈设只从**里面**的锚点算；全部锚点都在屋里时，这顶屋顶本来就不该出现，直接跳过。剩下的 20 条
都是角落里的树、石、芦苇——离任何锚点都超过一屏，属于布景冗余而不是穿帮，暂留作待清理。

### 水面按「哪里」上色，不按主题

原来 ruins/myth/night/dream 四个主题的水一律画成墨黑，结果太虚幻境的**灵河**成了黑墙。现在按场景：
迷津 `0x2f3a36`（墨）、火烧残迹 `0x39433f`、神话 `0x4c5a54`、夜 `0x53635f`，其余青绿 `0xa8c5c2`；
水面外加一圈湿岸，免得黑带读成竖起来的墙。

### 花圃要种东西

一格绿矩形在游戏实际缩放下等于草坪。花圃现在画一道矮篱、再按格撒花丛（三色花瓣 + 叶影），
一畦就能看出是花圃。

### 灯市：灯笼是画出来的

`lantern-booth` 画的是竹架，没有灯；元宵灯市因此像白天的空棚子。灯笼不必再等一张 1024 px 的
渲染（图模只要听到「灯笼」就会画一座院门），改由 `MapScene.lanterns()` 按 `lights` 逐点画：绳、
朱红纱面、金框、暖光、地面光斑。`lights` 是 TMJ 根属性 `col,row;…`，`dusk=true` 给地面压一层冷色，
只压地不压人物。灯市一行写成 `(c+k, r-k)`，屏幕上才是一条直街。

### 一张图一张图看下来的结论

- `suzhou`：甄宅与葫芦庙原来隔十四格，镜头里只剩空砖地；收到一墙之隔（甄宅 16–26 列、庙 7–15 列），
  书斋地坪 `[20,14,5,4]` 正好落在正房身下。
- `zhitong`：殿前院子是外场（rows 19–25），只有走进殿门（`rear`）才掀顶露出粥锅与佛龛。
- `c5_mijing`：北岸地坪原来铺到 row 21，黑水带上浮着几块浅色地砖；现在水占 rows 18–22，两岸各让开，
  木筏停在水上不靠岸。
- `c5_ningfu`：会芳园进园一段原来空着，补了花树与湖石；上房 `ning-hall` 限到 360 px 才在山脊进画面。
- `wang`：`south_passage` 收到 (23,23)，王夫人正房才从廊下看得见檐口。
- `c6_wangchui`：凤姐上房四周锚点相距 1300–2600 px，属于纯室内场次（进屋才掀顶），`wang-hall`
  高度由 `refit_stage_assets.py` 压到 470 px。

## 把看不见的布景挪回画面里（2026-10 末，续）

上一轮把取景做成了可以量化的检查，第一次跑出 20 条「这件东西永远不在画面里」。逐条看下来，分三类，
没有一条是「差一点」，都是摆在离任何锚点一屏之外的院墙角或对岸：

| 症状 | 图 | 根因 | 处理 |
| --- | --- | --- | --- |
| 迎门两株树在院墙外沿 | `central`、`east`、`lin`、`yucun`、`c4_yamen`、`c6_village` | 按「地图边缘填空」摆的，人只在甬路上走 | 挪进院子，靠在某一处锚点一屏内 |
| 三丛芦苇种在对岸 row 12 | `canal` | 锚点全在南岸 rows 25–29，垂直差 400px 再叠 320px 的苇高 | 一律移到水沿 rows 22–24 |
| 芦苇比树还高 | `canal` | 原图 372px，缩放 0.85–0.9 后 320px，比院里的树（270px）高 | 降到 0.6，齐人高 |

芦苇那条值得记：镜头预算是按**像素高度**算的，物件越高，能看见它的锚点就得越近。一丛 320px 的芦苇
只有站在它旁边才进得来，所以它要么缩小，要么没有意义。院墙角落的树同理——一株 270px 的树，站得比它
低六格（192px）就已经顶出画面上沿了。

### 凤姐上房：室内地坪画到了院子中间

`c6_wangchui` 的屋壳 `wang-hall` 在任何一个室外锚点都不进画面。真正的原因不是高度，是地坪：
`A2`（`indoor=true`）从 row 2 一直铺到 row 15，把影壁、台矶、堂屋全算成「屋里」。于是走到影壁，屋顶
就掀了；屋壳只在周瑞家那边画，而那边离它 1300px。改法是把室内地坪收回屋墙（row 2–9），把 `A1`
北沿补到 row 10 接上——影壁变成院子里的锚点，站在影壁前就是一张「正房正面」的镜头。

### 掀顶从来没触发过：`zoneAt` 返回第一个命中的矩形

同一轮里发现的运行时 bug。`zoneOccupied()` 判断「有没有人站在这个地坪上」时用的是
`zoneAt(map,col,row)?.id===zoneId`，而 `zoneAt` 返回**第一个**包含该格的矩形。屋内地坪永远嵌在院子
地坪里，而院子在 `zones` 里排在前面，所以永远命中院子，屋内地坪永远算「没人」：

- 贾政书房（`yucun`）：掀顶后屋里一件家具都不显示，两个人站在空地上说话；
- 甄宅书斋（`suzhou`）、智通寺大殿（`zhitong`）、贾母正房（`entry`）同理。

改成直接按命名矩形判包含（`this.mapData.zones.find(z=>z.id===zoneId)`），不再经过 `zoneAt`。这一类
「小矩形嵌在大矩形里」的地坪在全部 27 张图里都有，属于系统性问题，不是某张图摆错。

### 教训：不要 `git checkout --` 单个文件

清理运河芦苇时想「先还原再改」，对 `design/travel-maps.json` 跑了 `git checkout`——这个仓库的工作树
长期是大量未提交状态，那一撤把前几轮整份重设计（运河与郭外两张图的 props、terraces、beds）删掉了。
补救办法是从已生成的 `maps/canal.tmj`、`maps/guowai.tmj` 反解：`scale=width/native_width`，
`c-r=(x-(w/2-anchor_x)*scale)/64`，`c+r+1=(y-(h-anchor_y)*scale)/32`，一位不差地还原了 props，
再从 TMJ 的根属性补回 `terraces` / `beds`，重建后与原 TMJ 逐字段一致。这条已写进 `AGENTS.md`。

## 物件什么时候该让开：从「碰上就透明」到「确实挡住了」（2026-10 末，续二）

### 一、一张人物立绘被当成了墙上的画

`c5_ningfu` 的上房原来摆了一件 `wang-portrait`，注释写的是「正面挂着《燃藜图》」。但
`wang-portrait` 是**王夫人的肖像立绘**，248×600，和其它 60 多张 `*-portrait` 一样是给对话框
左栏用的竖幅人物像。它站进屋里，比案、椅、屏风都高出一大截，看上去就是一个大人杵在院子里。

已删除。原文那幅画的写法是：

- 上房：「抬头看见一幅画贴在上面，画的人物固好，其故事乃是《燃藜图》」，两边对联
  「世事洞明皆学问，人情练达即文章」；
- 秦氏卧房：「有唐伯虎画的《海棠春睡图》」，两边对联「嫩寒锁梦因春冷，芳气笼人是酒香」。

**没有做成地图物件**，原因是这个视角表达不了「墙」：屋壳 `exterior` 一掀，连墙带顶整座消失
（见上文「镜头预算」），只剩 `roomWalls()` 画的 30 px 墙裙，一幅 150 px 的立轴只能浮在地板上
方。试过贴北墙，但 `c5_ningfu` 的上房北墙（row 10）正好被秦氏卧房的屋壳压住，屏幕上完全不在
画面里；要让它露出来得把两进屋的地坪拉开，代价远大于收益。目前这两幅画由对话文本承担。

**教训**：素材名里有 `portrait` 的东西，一张都不该出现在 `Art` 层里。`check_content` 目前不查
这条，值得补。

### 二、半透明判定：矩形框回答不了「人在哪儿」

旧逻辑是「人物脚底投影落在物件精灵矩形内 → 物件半透明」。它分不清五种关系：

| 关系 | 旧逻辑 | 现在 |
| --- | --- | --- |
| 站在物件**里面 / 上面**（床、门洞、台矶、树根） | 淡 | 不淡 |
| 站在物件**前面**（脚线以南） | 不淡 | 不淡（按 `artGround()` 的脚线，不是位图底边） |
| 站在物件**后面**且真被挡住 | 淡 | 淡 |
| 从物件**旁边**擦过、落在矩形空角里 | 淡 | 不淡 |
| 整座**建筑**在后面 | 淡（整片灰） | 不淡 |

三处改动：

1. **脚线用 `artGround()`**。排序用的是它，判定却用位图底边，两者对 `flower-gate` 差 145 px。
2. **占地用接触阴影的椭圆**。`artwork()` 给每件东西画的影子本来就取自
   `min(width*.66,150)`，判定直接复用同一个椭圆 —— 两个数从构造上一致。落在椭圆内算「站在
   里面」，不淡。
3. **轮廓采样**。矩形对圆形的树冠、镂空的桌腿太宽松。`silhouetteOf()` 把每张纹理缩到 32×32
   读一次 alpha，存成网格；判定时从脚到头取 6 个采样点，问「这个 x 在那一行有没有画」，
   过半命中才算被挡。每张图只采样一次并缓存，启动从 0.9 s 变 1.5 s。

外加两条硬规则：

- **建筑外壳永不淡**（`visibility==='exterior'`）。掀顶已经处理了「人在屋里」；剩下只有「路过
  房子背面」，那时靠名字标签，而不是把 700 px 的房子变成灰雾 —— 淡成 45 % 之后既看不清房子，
  也照样看不见 85 px 的人。
- **淡出程度 45 %**。试过 60 %，树冠密集处仍然看不见人，只剩一层灰。

`ArtObject` 另有一个 `flat` 标记（贴在墙上的东西不参与遮挡），当前没有物件使用，留给以后的
匾额、挂画。

### 三、还没做的

`c1-home` 的甄士隐站在海棠和甄宅之间的缝里，树淡到 45 % 也只能勉强看见他。这是布局问题
（人物锚点卡在两件大物之间），不是判定问题。
