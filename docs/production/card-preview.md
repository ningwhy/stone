# 背包卡片页（card preview）

> 状态：2026-11-16 上线。数据层 `src/cardPreview.ts`，界面 `src/CardPreview.tsx`，
> 样式在 `src/styles.css` 末尾的「背包卡片页」一节。
> 入口：顶栏「背包」→ 账簿 → **点一个人或一样东西**。

## 一、它是什么

用户的话：

> 为背包里的所有物品、人物设计一个卡片页。参考卡牌类游戏的卡片预览弹窗的设计。
> 在背包里点击某个人物、物品的时候，弹出来。

「背包」就是账簿（`design/ledger.json`，54 笔）。账簿原先只是**索引**：一列名字、
一列小图，看得出有谁有物，却看不出这个人来历如何、那样东西又怎么转了几道手。
卡片补的就是这一层。

三条已确认的设计决策：

| 决策 | 取法 | 理由 |
| --- | --- | --- |
| 覆盖范围 | **只做背包（账簿）里的人与物** | 严格对应「背包里的」：账簿 54 笔涉及的 54 个人 + 51 类物品 |
| 卡片内容 | **剧情考据向** | 大图卡面 + 原文引文 + 情节说明 + 出场回目 + 流转时间线；信息全部来自已有底本与账簿数据，零新增数值、零臆造 |
| 美术来源 | **复用为主，缺的补画** | 已有资产直接用；缺货品图的物品补画卡面图 —— **实测后物品侧零缺口，一幅都没补**（见下） |

### 实测：物品侧其实不需要新画

盘点结论（54 笔账逐条实读）：

- 按 `what.split('（')[0]` 分组得 **51 类**物品/银两（注意：24 是 `item` 类别的条数，
  与「51 类物品」是两个口径，别混）。
- 其中 **47 类已有货品图**；另 4 类（`娇杏`/`袭人`/`鹦哥`/`英莲`）是 `person` 类，
  由 `ledgerEntryArt()` 兜底挂被转手者自己的立绘。
- **所以「缺的补画」这一项实际无需动渲染机**——物品侧美术零缺口。

真正要补的是**人物别名归一**与**无立绘人物的处理策略**，见第三、四节。

## 二、卡片结构

**一张竖版卡牌摆在桌面上，右边跟着这一张卡的账。**
像卡牌游戏的预览那样：先看画，再看名，最后才看账。

```
   ┌─────────────┐   ┌────────────────────────────────┐
   │ 人      3/4 │   │ 背包 · 人                       │  ← 属性条：类别 + 入账笔数
   ├─────────────┤   ├────────────────────────────────┤
   │             │   │ 3/4 笔入账 · 出场于 第一回、…    │  ← 这一张卡的本事
   │   完整立绘   │   ├────────────────────────────────┤
   │  （全身）    │   │ 流转时间线                       │
   │             │   │ ┌────────────────────────────┐ │
   │             │   │ │赠与│ 白银五十两             │ │  ← 方向徽章 + 品名
   ├─────────────┤   │ │    │ 甄士隐 → 贾雨村            │ │  ← 谁 → 谁
   │   贾雨村     │   │ │    │ 情形说明…                  │ │  ← 情节说明
   │ 黛玉的塾师   │   │ │    │ 「原文引文…」              │ │  ← 原文引文（竖线缩进）
   └─────────────┘   │ │    │              第一回         │ │  ← 回目印章
      竖版卡牌        │ └────────────────────────────┘ │
   （卡纸 + 画框）    │ ┌────────────────────────────┐ │
                     │ │？ │ ？？？                    │ │  ← 未入账：只留一个「？」
                     │ │    │ 读到这一笔的剧情后入账     │ │
                     │ └────────────────────────────┘ │
                     └────────────────────────────────┘
                        账本面板（内容长了自己滚）
```

### 为什么是竖版

**立绘是窄长的一幅**——多数 600 高、190~350 宽（`yinglian-portrait` 是 301×600，
`yucun-portrait` 是 317×600）。横版画框塞不下全身，只能裁：

- 早先按 `faceBox` 裁头肩近景 → 看得见脸，**看不见人**；
- 改成 `object-fit:cover` 铺满 → 头顶或脚底被切掉。

竖版画框（宽高比 5:7）+ `object-fit:contain` → **整幅立绘从头到脚都在**，
人站在画框里，脚底压一层薄墨，像是站在暗处。

### ★ 但「整幅都在」不等于「画到了脚」

这一点必须说清楚，否则下次还会把资产的事当成裁切的事来查：

**立绘资产本身就是半身到大半身像，不是全身像。**

| 资产 | 尺寸 | 画到哪儿 |
| --- | --- | --- |
| `yinglian-portrait` | 301×600 | 头 → 裙摆（**没有脚**） |
| `yucun-portrait` | 317×600 | 头 → 袍摆（**没有脚**） |
| `yinglian-chibi` | 44×80 | **全身**（大头身 Q 版，有脚） |

81 个立绘资产的宽高比从 0.245（`she_yue-portrait` 147×600）到 0.912（`kongkong-portrait` 547×600），
**都是同一套「头部特写 + 大半身」的画法**，不是全身立绘。
像素实测（`yinglian-portrait` 逐行 alpha）：底行 maxAlpha=255、meanAlpha=213 → **硬切，没有渐隐**，
说明人物是被画布边缘截断的，不是淡出。

→ 所以「显示全」的准确含义是：**画框里放的是这资产的完整原图，一像素都不裁**。
   想要真正从头顶到脚底的全身像，只能重画立绘（或用 Q 版，但那是另一个画风，
   放不进这张写实卡面）。

> ★ 断言口径也要跟着改：**不能**断言「画框底部能看到脚」——
> 那是在断言美术管线的能力，不是断言卡片页。
> 卡片页能保证的只有「不裁、不切、整幅缩进去」。

### 卡名为什么不在画上

卡名与副题在**画框之外的卡纸上**（深墨字压在米色卡纸）。
压在画上就要靠一层很重的墨色渐变托底，一重就把画闷掉了；
挪到卡纸上，字始终清楚，画也干净。

### 字段契约（`CardPreview`）

| 字段 | 说明 |
| --- | --- |
| `title` | 卡名：人名或品名（卡纸上下缘那一段，深墨字） |
| `subtitle` | **只补卡名没说的那部分**：人物——账上写简称才补全名，再加关系（账上已写全名就只留关系）；物品——流转链的首尾（「甄士隐 → 贾雨村」），不重复属性条上的类别 |
| `category` | 账上类别（决定卡面配色，`.cat-person` 等；卡牌顶部属性条与面板抬头都用它） |
| `badge` | **数据层字段，界面已不用**：现在属性条直接取 `categoryNames[category]`（人 / 银两 / 衣物 / 物件 / 人情），不必再维护第二份文案 |
| `art` | `portrait` / `goods` / `seal` —— 大图的来路 |
| `artKey` / `artSrc` | 立绘资产名（`<actor>-portrait`）或货品图路径 |
| `actor` | 对应的 cast 角色（有则可跳图鉴） |
| `seal` | 花押用的首字（`art==='seal'`） |
| `books` | 出场回目（升序去重）——**只算已入账的那些回** |
| `flows` | 流转时间线，每笔一项 `CardFlow` |
| `got` / `total` | 已入账笔数 / 总笔数（卡牌右上角 `3/4` 与面板属性带都用它） |

`CardFlow`：`id / what / category / mode / from / to / amount / book / node / circumstance / source / unlocked`。

### 未入账不泄露（硬纪律）

**未入账的一笔，`what` / `from` / `to` / `amount` / `circumstance` / `source` 全部留空**，
界面上只留一个「？」。账上写明了什么，得等读者读到那一回才算数。

**`books`（出场回目）同样只算已入账的那些回**——口径与 `LedgerRow` 一致（未入账的账连回目印都不露）。
只读到第一回时，卡片不该写「出场于 第一回、第二回、第三回、第四回」：
那三回读者还没读到，写出来就是剧透。`unlockedBooks()` 负责这件事。

**物品卡的副题也一样**：它说流转链的首尾（「甄士隐 → 贾雨村」），
一笔都还没入账时只写「尚未入账」——说得出从谁到谁同样是剧透。

这条纪律在 `src/cardPreview.ts` 的 `toFlow()` 与 `itemSubtitle()` 里落地，并由
`tests/card-preview.test.ts` 的「未入账的账不泄露」「没读到的回不当剧透」两节钉住。

> 实现记录：最初 `toFlow()` 只对 `source` 与 `circumstance` 做了遮蔽，
> 单元测试当场抓出 `what`/`from`/`to` 仍在泄露——这是写测试的收益，不是形式。

## 四、无立绘人物：落一方花押

12 个账上人归一之后仍然没有像 → 落一方**朱印式花押**（`.card-face-seal`），

| 类别 | 名字 | 理由 |

| 未曾登台 | `贾敬` `贾赦` `王子腾` `冯渊` `拐子` `胡老爷家太太` `张（金哥之父）` | 账上有名字，戏里没出场 |

> 「北静郡王」「甄家娘子」**有**像——它们分别归一到 `shui_rong`（水溶）
> 与 `fengshi`（封氏，士隐之妻），不在这张表里。
> 这张表是「归一之后仍然没有像」的名单。

> ⚠️ 文档写什么不算数，**实测才算数**。这张名单是跑
> `ledgerActors()` + `ledgerActorOf()` + `artAssets` 实测出来的，
> 不是照抄 `src/ledger.ts` 里的旧注释（那边还写着「甄家娘子未出场」，
> 那已经过时了）。

**绝不为凑齐而画一张像**：立绘是「这个人长什么样」的凭据，画不出来就是画不出来，
花押比一张编造的图诚实。

## 五、弹窗层级：为什么用独立的原生 dialog

卡片层**不塞在册页那个 `<dialog>` 里**，而是另起一个 `dialog.preview-dialog`：

- 原生 `showModal()` 走浏览器**顶层（top layer）**，盖在册页之上不会被册页的
  滚动容器裁掉；放在册页内的定位层会被册页的 `overflow` 与层叠上下文吃掉。
- `Esc` 由 `onCancel` 接管（`preventDefault()` 后走 `onClose`），与册页自己的
  关闭逻辑不打架。
- 关掉卡片就回到背包列表——**不是另开一页，是把账簿摊开一张**。

与既有 `pickup-overlay`（获得物品的模态层）不同：那个是 `position:fixed` 的普通层，
而卡片需要压在 `<dialog>` 之上，普通层做不到。

### 点击行为的改动

账簿列表项的点击**从「切换选中」改为「摊开卡片」**，同时仍然把右侧的流转链换过来：

```tsx
onClick={()=>{setLedgerPerson(p.name);setPreviewCard(personCard(p,ledgerUnlocked));}}
```

> 这一改动会影响 `tests/browser-smoke.mjs` 里那条
> 「点贾雨村 → `.ledger-summary` 出现贾雨村」的断言——它仍然通过，因为
> 右侧的流转链照旧换成了贾雨村那一栏，只是多弹了一张卡。

### ★ 一个坑：`dialog` 的 `margin:auto` 只在尺寸固定时才算居中

第一版弹框**不居中**——卡片贴在左上角，右侧空一大片。

`dialog` 的 UA 默认样式是 `position:absolute; left:0; right:0;`，
一个**撑满全宽**的绝对定位盒。`width:auto` + `inset:0` + `margin:auto`
看着该居中，实际不行：

```
A: inset+margin:auto          → computed margin: "0px"，盒子 1280×720（=视口）
B: inset+margin:auto!important→ computed margin: "0px"，盒子 1280×720（=视口）
C: width:860px + margin:auto  → computed margin: "260px 210px"，盒子居中 ✓
```

**`auto` 的外边距只有在尺寸确定时才有意义**；`width:auto` 时它退化成 0。
所以要么给死宽度，要么换一种居中办法。这里给死宽度（`height:fit-content` 让高度跟内容走）：

```css
dialog.preview-dialog{
  width:min(820px,calc(100vw - 24px));height:fit-content;max-height:92vh;
  inset:0;margin:auto;
}
```

> ★ 断言也要小心：光断言「中心离视口中心多远」是**抓不住**这个 bug 的——
> 撑满全屏的盒子，中心恰好也在视口中心（实测 offX=0、offY=0）。
> 必须**同时断言盒子尺寸**（不该等于视口）。

### 一个坑：图片「加载成功」不等于「画出来了」

上线后的第一张线上截图里，**卡面是一片空白渐变**——没有脸。
而所有自动断言都绿了：`naturalWidth: 317`，图片明明加载成功。

原因在 CSS 层叠：

```css
/* 册页卡片（既有）的通用规则：卡面里的文字要浮在图上面 */
.card-face>*:not(.card-thumb):not(.card-blank){position:relative;z-index:2}
```

这条规则的特异性是 **(0,3,0)**——两个 `:not()` 各计一个类，再加 `.card-face`。
我写的 `.preview-face .card-face-portrait` 只有 **(0,2,0)**，**输了**，
于是 `position: absolute` 被覆盖成 `relative`：

- `relative` + `inset:0` 不会撑开盒子 → holder 变成 `height: 0`；
- 图片跟着塌成 `0×0`；
- 但 `<img>` 的 `naturalWidth` 仍然是 317 —— **图片确实加载了，只是没有尺寸可画**。

修法：把选择器写成同等特异性、靠后出现即可取胜：

```css
.card-face.preview-face>.card-face-portrait{position:absolute;inset:0;…}
```

> 通用规则没有改——它是册页卡片的既有行为，只是不该误伤新加的图容器。
> 同样的坑也踩在 `.preview-badge` / `.preview-title` / `.card-face-seal` 上，
> 一并改成了 `.card-face.preview-face>…`。

**教训**：`naturalWidth > 0` 只证明图片下载到了，不证明它画在了该在的地方。
验收要**量盒子**（`getBoundingClientRect()`），并且**看图**。

### 同一个通用规则的第二个坑：`z-index` 也要压

修好 `position` 之后，图是画出来了——**可脚下那层墨不见了**。

原因还是上面那条通用规则。它除了 `position:relative`，还给了 `z-index:2`：

```css
.card-face>*:not(.card-thumb):not(.card-blank){position:relative;z-index:2}
```

于是**立绘容器被抬到 `z-index:2`**，而画框下缘那层落地影
`.preview-face::after` 只有 `z-index:1` → **影被立绘盖住了**。

修法是**三处都要压 `z-index`**（不只是 `position`）：

```css
.card-face.preview-face>.card-face-portrait{…;z-index:0}   /* 立绘 */
.card-face.preview-face>.card-face-seal{…;z-index:0}       /* 花押 */
.card-face.preview-face>.card-face-img{…;z-index:0}        /* 器物图 */
```

> ★ 通用规则同时动了 `position` **和** `z-index`，只解一个不够。
> 下次再往 `.card-face` 里加东西，记得两个都要压。

> ★ 现在卡名已经挪到卡纸上（见「卡名为什么不在画上」），
> 画框下缘这层墨**不再承担「垫字」的职责**，只留很薄的一层落地影——
> 压太重会把人物的脚底压脏。

### ★ 有些毛病只有像素能看见：读截图

上面两个坑，**DOM 全都看不出来**：

- 图片在 DOM 里、`naturalWidth` 是 317、`getBoundingClientRect()` 也非零；
- 渐变在 DOM 里、`::after` 确实存在、也确实 `position:absolute`。

但读者看到的是「一张空卡」和「看不清的字」。
**只有把像素读出来才知道**。

所以 `tests/lib/png.mjs`（自写的最小 PNG 解码器，项目没有 pngjs/sharp）
用来读 Playwright 截出来的图，`tests/card-preview.mjs` 里有一条
`checkNameLegible()` 对**三种卡**（人物 / 物品 / 花押）各查一遍。

**卡名现在在卡纸上**（深墨字压米色卡纸），判据与上一版不同：

| 判据 | 含义 | 实测（修好后） |
|---|---|---|
| 卡名行**墨迹跨度内**的墨迹占比 `> 15%` | 那行真的有深色的字 | 35.0% / 27.8% / 48.3% |
| 卡名行**墨迹跨度内**的纸面均值 `> 150` | 字压在浅色卡纸上 | 162 / 182 / 153 |

> 判据怎么取「那一行」：`strong` 是 block，盒子占满整行（272px），
> 字只在中间一小段。所以扫一整行 → 取**首末暗像素之间的跨度** →
> 只在这段里算墨迹占比与均值。整行均值会被左右空白稀释，
> 算出来会误判成「没有字」。

> ★ 旧判据（「卡面下缘亮度 < 110」「亮笔画占比」「峰均差」）是为
> 「字压在图上」那版结构写的，卡名挪到卡纸后**全部作废**，别再照抄。

## 六、门禁与验收

```bash
npx tsc --noEmit                              # 类型
npm test -- tests/card-preview.test.ts         # 数据层 13 项
node tests/card-preview.mjs                    # 浏览器定向验收
npm run test:online:card-preview               # 线上复验（部署后）
```

`tests/card-preview.test.ts` 钉住：

1. 别名归一（12 条显式别名）；
2. 别名**不**靠模糊匹配（`冯家`/`张（金哥之父）`/`宁国府` 必须落空）；
3. 每个人与物都有卡，笔数对得上；
4. 大图都指向真实存在的资产；
5. 被转手的人（英莲）挂自己的立绘；
6. 没画出像的人落花押；
7. **落花押的名单是固定的**（归一后仍无像的恰好那十二个；`北静郡王`/`甄家娘子` 必须有像）；
8. **副题只补卡名没说的**（不重复卡名；账上写简称才补全名）；
9. **未入账不泄露**（原文、情形、品名、双方全部为空）；
10. **没读到的回不当剧透**（出场回目只算已入账的）；
11. 入账后原文与情形才露出来；
12. 流转一行说得清；
13. 一笔账能找回它两头的卡片。

`tests/card-preview.mjs`（浏览器）钉住：

1. 点人物 → 卡片弹出；
2. 卡片有大图、卡名、流转时间线、原文引文、情形说明；
3. 大图**真的加载出像素**（不是只挂在 DOM 里）；
4. **大图真的有可见尺寸**，且**整幅图完整落在画框里**（`overlapRatio > 0.98`）；
5. **整幅立绘是缩进去的、不是被裁的**（算 contain 后的实际绘制尺寸 ≤ 画框，且高度填满 > 80%）；
6. **卡片真的像一张卡**（`checkCardLooksLikeACard()`）：
   - 弹框**居中**（横竖偏差 < 12px）**且盒子是卡牌大小**（≤ 视口 92% / 94%）；
   - 卡牌与画框**高 > 宽**（竖版）；
   - 图的 `object-fit === 'contain'`；
7. **卡名在卡纸上真的看得清**（读像素：墨迹占比 > 15%、纸面均值 > 150）——人物 / 物品 / 花押三种卡各查一遍；
8. 未入账的账只留「？」；
9. 关掉卡片后**仍在背包**（册页还在、列表还在）；
10. 点物品同样弹出（英莲三笔同链都列出）；
11. 无像的人落花押，**不出现坏图**，且花押**铺满卡面**；
12. 再点同一人收起卡片、账簿回到 54 笔总账；
13. 全程零 JS 错误。

> 第 6 条的判据来自实测：**回退固定宽度后立刻报**
> `the card must be a card-sized box, but it spans 1440px of 1440`；
> 把 `contain` 改成 `cover` 立刻报
> `the picture must fit whole in the frame, got object-fit:cover`。
>
> ★ 只断言「中心离视口中心多远」**抓不住**不居中的 bug——
> 撑满全屏的盒子中心恰好也在视口中心（offX=0、offY=0），
> 必须**同时断言盒子尺寸**。

`tests/online-card-preview.mjs`（线上）钉住：

1. 点人物 → 卡片在账簿之上弹出；
2. 卡名对得上、卡面有图、有流转、有引文、有回目印；
3. 大图**从源站真的取回像素**；
4. **卡片报的回数 == 已入账的回数**（不剧透没读到的回）；
5. **线上也是一张卡**：弹框居中且是卡牌大小、卡牌与画框高>宽、`object-fit === 'contain'`；
6. **卡名在卡纸上真的看得清**（读线上截图的像素）；
7. 关掉卡片 → 账簿仍在；再点同一人 → 回到 54 笔总账；
8. 全程零 JS 错误。

> 第 6 条实测（本地）：
> 人物 `{"paperMean":162,"inkRatio":0.35}`、
> 物品 `{"paperMean":182,"inkRatio":0.278}`、
> 花押 `{"paperMean":153,"inkRatio":0.483}`。
> 线上才是读者真正看到的地方，所以这条判据在线上也要跑一遍。
