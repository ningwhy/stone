# 信物 · 物品获得模块 · 设计与实施

> 状态：**已实施**（2026-10-26）。四件信物入库（护官符为首件），四件人的归属入库（袭人为首件）。
> 落点：`design/collection-cards.json`（`kind: "token"`）、`src/collection.ts`、`src/App.tsx`（册页「信物」组）、`scripts/check_content.mjs`（引文校验）。
> 与 `collection.md` 的关系：本文是它的**第三类卡**（信物卡）的实施细则；地志卡与金句卡见那篇。

---

## TL;DR

可以做，但**不是背包系统**。

前四回原文里可持有的「物」只有 5 件，其中 4 件是银两绸缎这类一次性交付物——收进背包没有叙事回报，做出来就是个空壳。真正值得做的是**信物**：原文写明「交到手上」、且改变剧情走向的那件东西。

因此本模块的形态是：**信物册**——护官符在第四回「从顺袋中取出一张抄写的『护官符』来，递与雨村」那一刻入册，卡面是那张抄本本身。

| 项 | 值 |
| --- | --- |
| 已入库信物 | 4 件（护官符、密书、花帐锦被、赠银） |
| 已入库归属 | 4 人（袭人、鹦哥、娇杏、甄英莲），方向分赏给/买卖/被夺 |
| 归类判据 | 原文写明交到某人手上 + 有专属内容 + 能指向后续 |
| 解锁方式 | 与地志卡同一套 `readLog` 判定（读到获得那一刻的节点） |
| 新增美术 | 0（卡面是抄本形制的排版 + 已有印章纹样） |
| 引擎改动 | 0（`readLog` 已是现成事实，存档不升版本） |

## 一、先做核查：前四回到底有几件「物」

这是决定模块形态的关键一步。底本 `docs/chapter0N-source.txt` 逐句正则扫描 + 人工剔除「携人」「与人」这类误报后，全量命中如下：

| 回目 | 物 | 原文依据 | 是否入库 |
| --- | --- | --- | --- |
| 一 | 五十两银子、两套冬衣 | 「我贈五十兩銀子、兩套冬衣，路費由我相助」 | ✅ |
| 二 | 一封密书 | 「又寄一封密書與封肅，轉托問甄家娘子要那嬌杏作二房」 | ✅ |
| 三 | 藕合色花帐、锦被缎褥 | 「熙鳳命人送了一頂藕合色花帳，並幾件錦被緞褥之類」 | ✅ |
| 四 | 护官符 | 「從順袋中取出一張抄寫的『護官符』來，遞與雨村」 | ✅ |
| 一 | 银衣 | 「雨村收了銀衣」 | ❌ 见下 |
| 二 | 两封银子、四匹锦缎 | 「雨村遣人送了两封银子，四匹锦缎」 | ❌ 见下 |

**剔除的两件**：`银衣`与`两封银子四匹锦缎`都是**一次性交付物**——它们在原文里是「酬谢」这个动作的宾语，收进册子后没有任何后续。它们真正承载的内容是「酬谢甄家」「答谢娘子」这层**关系**，而关系已经由人物卡承担了。

**另外两处需要说明**：

- 贾母「與了黛玉」鹦哥、「與了寶玉」袭人——这是**给人不是给物**，归人物卡，不进信物册。
- 第五回以后的通灵宝玉、鸳鸯剑、虎兕相逢一香等等，才具备「随身信物」的性质，是后续回目的扩展方向，不在首期范围。

## 二、判据：什么才算一件信物

三条同时成立才算：

1. **原文写明交到手上**——有「递与」「取出一张…来」「送了一顶…」这类明确动作，不能是「提及过」。
2. **有专属内容**——物件本身承载可展示的内容（护官符的四句符文、密书的托付内容），而不是一个通用货币单位。
3. **能指向后续**——拿到它之后，剧情或人物关系有变化。

第 1 条是硬门槛：**不制造原文没有的持有关系**。这是 AGENTS.md 里「原文明示 / 人物转述 / 设计推定分开记录」的延伸——如果原文只说「他有个玉」，就不能写成「他获得了玉」。

第 3 条是软门槛，用于**取舍**而非准入：像「两封银子」这种属于一次性交付物，即使满足 1、2 也不入库。

## 三、数据形状

在 `design/collection-cards.json` 里，`kind: "token"`：

```jsonc
{
  "id": "token.huguanfu",
  "kind": "token",
  "book": 4,
  "name": "护官符",
  "subtitle": "一张抄写的本省大族名宦口碑单",
  "quote": "贾不假，白玉为堂金作马。\n阿房宫，三百里，住不下金陵一个史。\n东海缺少白玉床，龙王来请金陵王。\n丰年好大雪，珍珠如土金如铁。",
  "attribution": "应天府门子 呈与贾雨村",
  "node": "C04-029",
  "unlock": { "type": "read", "node": "C04-029" },
  "source": "從順袋中取出一張抄寫的「護官符」來，遞與雨村"
}
```

- `node` 与 `unlock.node` 必须是同一个节点：这个节点就是「东西到手的那一刻」。
- `source` 是**繁体原文依据**，供卡面落款与校验使用。
- `quote` 是卡面展示的内容（护官符是那四句符文）。

## 四、防腐化：引文必须逐字对得上底本

信物卡最容易腐烂的地方是——引文慢慢和底本脱节，卡面就在替原文说话。所以加了一道**门禁**：

```
check_content 校验：信物卡的 source 去掉空白后，必须逐字出现在
docs/chapterNN-source.txt 中，否则 WARN。
```

这是本模块唯一的新增校验，也是我认为最值得保留的一条。设计稿 `collection.md` 第十节原本只要求校验「节点存在、锚点存在」，但信物卡的额外风险是**引文造假**，所以单独加了这一条。

## 五、卡面

信物卡的卡面不用新美术，用**抄本形制**：

- 纸色比地志卡更旧（`#f3ecd8 → #e9dfc4`），四角无框，像一张散页
- 护官符的 `quote` 按 `\n` 拆行竖排四行（用「贾不假」这样的短句分行，而不是整段）
- 右上/右下压朱印（`#9c3b28`），印文是**交出者与受者**（"应天府门子 呈与贾雨村"）
- 卡下 `source` 字段以小字标出原文依据，让读者知道这不是编的

信物卡比普通卡高（`min-height:196px`）——护官符四行符文 + 落款 + 朱印，170px 装不下。

## 六、归属卡：那个年代，人也可以是「给」的

> 追加于 2026-10-26。起因是一个更准的观察：**袭人确实是「属于」宝玉的**——
> 贾母把她给过去，她就是宝玉的丫鬟，和给一件东西没有分别。原文用的就是同一个
> 「与」字。

### 6.1 为什么不并进信物卡

因为**把袭人写成物品是错的**。她有名字（本名珍珠）、有改名来历、有心事、会规谏主人；她的归属改变了她的一生（「伏侍賈母時，心中眼中只有一個賈母，如今服侍寶玉，心中眼中又只有一個寶玉」）。这些是信物卡装不下的分量。

更重要的是**方向**。同一个「与」字在原文里至少有三个意思：

| 方向 | mode | 原文用词 | 性质 |
| --- | --- | --- | --- |
| 赏给 | `granted` | 「遂與了寶玉」 | 恩主分派，附带效忠 |
| 买卖 | `sold` | 「要那嬌杏作二房」 | 聘娶为妾，附带交易 |
| 被夺 | `taken` | 「偷賣與薛家」「拖了去」 | 拐卖掠夺，附带暴力 |

赏给和被夺用的是同一个「与」字，意义完全相反。把它们混在一类里，册子就在替原文说错话。所以归属卡必须**单列一卡种 `kind=bond`**，并在卡面上标出方向。

### 6.2 原文里人的归属共四件

| 回目 | 人 | 从 → 到 | 方向 | 节点 |
| --- | --- | --- | --- | --- |
| 二 | 娇杏 | 封肃 → 贾雨村（后扶正为正室夫人） | 买卖 | C2-004 |
| 三 | 鹦哥 | 贾母 → 黛玉 | 赏给 | T004 |
| 三 | 袭人 | 贾母 → 宝玉 | 赏给 | T006 |
| 四 | 甄英莲 | 甄士隐 → 拐子 → 冯家 → 薛蟠 | 被夺 | C04-055 |

四人在 `src/story.ts` 的 `cast` 里**都已有身份定义与立绘**，所以归属卡不需要新美术，也不需要造人。

### 6.3 卡面

卡面是一行关系：**从谁那里来 → 到谁那里去**，右上角一个方向签（赏给 / 买卖 / 被夺，三色区分），下面一行简述。

```
┌─────────────────┐
│            赏给 │  ← 方向签，绿/棕/红
│ 贾母  →  宝玉  │  ← 归属两端
│ 原名珍珠，因心地 │  ← 简述
│ 纯良……遂与了宝玉│
│         第三回  │  ← 朱印
└─────────────────┘
```

与人物卡互补：**人物卡说「他是谁」，归属卡说「他属于谁」**。第二回娇杏那条尤其值得看——一个回顾换来一场奇缘，一年后生子，又半载原配病故便扶正为夫人。这是全书第一次写「一个丫鬟的命运被改变」。

### 6.4 与「证据分层」的关系

AGENTS.md 规定「原文明示、人物转述、设计推定分开记录」。归属卡天然遵守这条：

- 卡上的 `from` / `to` / `mode` **全部来自原文**；
- 卡面的「说明」是原文的直接转述，不是设计解释；
- 「赏给 / 买卖 / 被夺」这三个标签是**对原文用词的分类**，不是评价。

如果某条归属只能靠推断成立，就**不做这张卡**——例如原文未写明雪雁归黛玉，那就不能画「贾母 → 黛玉 · 雪雁」。

### 6.5 门禁

- 归属卡的 `actor` 必须存在于 `cast`（不能凭名字造人）；
- `bond.mode` 必须是三种之一，`from` / `to` 均不得为空；
- `source` 引文去空白后必须逐字出现在 `docs/chapterNN-source.txt`。

## 七、明确不做的事

| 不做 | 原因 |
| --- | --- |
| 通用背包 / 物品栏 | 前四回只有 5 件物，4 件是一次性交付物。背包系统会是个永远只有两三格东西的空壳 |
| 物品的使用 / 消耗 / 效果 | 这是阅读游戏，没有战斗也没有数值。护官符的作用已经由剧情本身承担 |
| 数值化的持有度、财富 | 同上 |
| 「获得」动作进引擎 | 现有动作类型只有 show/move/hide/roof/parallel/effect。加 `acquire` 会让引擎开始知道「收藏」这件事，破坏 `collection.md` 定的「引擎零改动」边界。解锁判定读 `readLog` 即可，不需要新动作 |
| 把人当物品列进信物卡 | 袭人、鹦哥是人，不是物。已另立归属卡（第六节） |
| 给归属卡加「使用」「反抗」等机制 | 原文里袭人的归属改变了她的一生，但那是人物线，不是机制。归属卡只记录关系，不模拟 |

## 八、后续扩展方向

- **第五回起**：通灵宝玉（随身、贯穿全书的信物）、鸳鸯剑、北静王鹡鸰香念珠，都是标准信物。届时信物册会自然长大，卡面需要各自的形制（玉的挂绳、剑的格、香的锦囊）。
- **信物影响后续**：如果某件信物在后文有明确作用（如护官符对应的徇情枉法），可以在册页里加「此物如何改变了一件事」一行，把收集和阅读再绑紧一层。
- **册页拼合**：`collection.md` 第五节的《护官符》册页，正好可以由这件信物作为核心。

## 附：核查方法（可复现）

```bash
# 逐句扫描底本里的「获得类」动作 + 物品候选，人工剔除「携人」「与人」
python3 - << 'EOF'
import re,glob
for f in sorted(glob.glob('docs/chapter0*-source.txt')):
    for s in re.split(r'[。！？\n]', open(f,encoding='utf-8').read()):
        if re.search(r'(遞與|递与|取出一|送與|送給|與了|收下|交了)',s) and re.search(r'(銀|银|書|书|帖|符|帳|帐|緞|缎|錦|锦|石|玉|扇|帕|錢|钱)',s):
            print(s.strip()[:100])
EOF
```

命中结果里绝大多数是「與某人」「攜某人」这类误报——**筛选获得物时必须先过滤掉以人为宾语的句子**，这是这一步最容易翻车的地方。
