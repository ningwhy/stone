## 一、账簿是什么

用户的话：「只要是获得和给出，我们都需要记录。」前四回里凡原文写明的转手——
银两、衣物、物件、人、人情——记成一笔账：**什么东西，在谁与谁之间，以何种方式，
什么情形下，什么价钱，在哪一章节转的手。**

它回答两类问题：

1. **谁在赚钱，谁在花钱**——每个有账目的人有一个净额（只计原文写出两数的账）。
2. **一件东西的流转史**——全部流转按剧情先后排布，护官符、娇杏、英莲的每一次换手都看得到。

## 二、一笔账的字段

| 字段 | 说明 |
| --- | --- |
| `what` | 转手物：`白银五十两`、`冬衣两套`、`娇杏`、`护官符抄样`…… |
| `category` | `money` 银两 / `clothing` 衣物 / `item` 物件 / `person` 人 / `favor` 人情 |
| `from` / `to` | 转手双方。多人按顿号拆分（`贾政、王子腾` 两人都算收到） |
| `mode` | 见下节，四方向 |
| `amount` | 原文**明确写出**的银两数；「两封」「许多」不折算，记 `null`，不计入净额 |
| `node` | 挂载的剧情节点，解锁依据 |
| `circumstance` | 一句话情形说明 |
| `source` | 原文引文，逐字对底本（门禁校验） |

## 三、转手四方向

与归属卡同一观察：同一个「给」字在原文里意思并不相同，必须分列。

| mode | 名 | 色 | 例 |
| --- | --- | --- | --- |
| `granted` | 赠与 | 绿 | 士隐赠银五十两、贾母与宝玉袭人 |
| `sold` | 买卖 | 棕 | 封肃卖娇杏、拐子两卖英莲、封肃半哄半赚的置办 |
| `taken` | 强夺 | 红 | 薛蟠夺英莲（所谓买，实是夺） |
| `paid` | 赔付 | 灰蓝 | 薛家与冯家的烧埋银子 |

## 四、金额纪律

- 只有三笔写了明确的数：五十两（士隐赠银）、二两（雨村赠封肃）、百金（娶娇杏聘资，按一金折一两的通行记法）。
- 「两封银子」「许多烧埋银子」一律 `amount: null`——账面不替原文编数字。
- 净额 = 有数之账的代数和。封肃 +102 两（前两回最赚的人），雨村 −52 两（收五十、出百金并二两）。

## 五、解锁与存储

- 与卡片同一规则：读到 `node` 即入账（readLog 推导 ∪ localStorage 历史）。
- 存储 key：`honglou.ledger.v1`，坏 JSON 容错返回空集。
- 未入账的条目在账面上显示为墨色「？」行，不提前剧透。

## 六、门禁

`scripts/check_content.mjs` 对账簿 WARN 级校验（与卡片同原则，先 WARN 后 FAIL）：

- `mode` / `category` 枚举合法；
- `from` / `to` 非空；
- `node` 必须真实存在于剧情节点；
- `amount` 若有必须为正数；
- `source` 引文去空白后必须逐字出现在 `docs/chapterNN-source.txt`。

## 七、与信物册、归属卡的关系

三者为同一事实的三种视图，不合并：

- **信物卡**回答「这个东西现在在谁手里、长什么样」；
- **归属卡**回答「这个人归了谁」；
- **账簿**回答「一路上谁给了谁什么、谁赚谁花」。

例：袭人既是归属卡 `bond.xiren`，也是账簿 `ledger.grandmother-xiren`；英莲在账簿里有三笔
（卖冯渊、偷卖薛家、被夺），归属卡只记最终归属。

## 九、获得弹窗

读到「交到手上」的账簿节点时，阅读流中弹出游戏式获得弹窗（`pickup-overlay`）：
货品图、品名、方向徽章、双方与银两数、情形说明，读者点「收下」才继续。
弹窗即存档：确认后条目写入 `honglou.ledger.v1`，重读、跳回、刷新都不再弹第二次；
弹窗打开期间演出暂停（与设置面板同一 overlay 通道），自动播放与空格键都被扣住。

这改变了一个旧约定：册页卡片的反馈仍然只在面板里（阅读中不弹窗），
但**账面上的「给」是剧情事件本身**——原文里这一刻就是双手相递，弹窗是演出的延续，
不是打扰。
