# 网页布局、交互与展示规范

## 既定信息布局

PC 横版竖向空间优先给地图。顶部一行约 60px，聚合品牌、段落下拉、进度、自动、回看、暂停/继续、推进、设置。当前地点只在地图左上显示一次，不恢复大标题区、重复章节/地点介绍或底部播放控制栏。

地图作为 story-stage 全尺寸底层，局部地图不因对白/行动切换而重新分配高度。桌面对白默认 160px，≥1700px 的现有规则为 170px；行动默认 104px。手机 ≤700px，顶部约 96px 两行，对白 205px，行动 105px。以 CSS 媒体查询实际规则为准，不把所有视口都锁死同一数值。

立绘绝对定位于对白框，头肩可突出。讲话人在左，在场人物在右；对白正文有固定左右内边距，不能被立绘挤压。不同原图高度只影响图片 contain 展示，不得撑高容器。对白内部溢出滚动，主页面不靠纵向长滚动容纳核心控件。

## 首次加载与竖屏引导

- `index.html` 内置 boot-splash（纸色印章字），覆盖打包下载阶段；React 挂载后由 `LoadingScreen` 接管。
- `LoadingScreen`（src/LoadingScreen.tsx）进度接 MapScene `load.on('progress')` 真实值；黛玉、宝玉、凤姐三个 Q 版沿进度条错落奔跑（CSS bob，遵守 prefers-reduced-motion）。场景 `onReady` 后 450ms 淡出、600ms 卸载；另有 12s 兜底超时，Phaser 启动失败也不把读者关在加载页。
- 竖屏手机（≤820px portrait）显示 `RotateHint` 横屏邀请，含旋转手机动画与黛玉 Q 版；点"仍要竖屏浏览"后写入 localStorage 不再提示，布局本身不变（390×844 仍走 ≤700px 规则）。产品主舞台是横版，不做完整竖屏重排。

## 播放状态与操作

| 状态 | 预期 |
| --- | --- |
| reading | 对白稳定显示，可继续、回看、保存 |
| moving / effect | 以行动提示突出地图，继续按钮用于跳过移动；行动结束才记录稳定对白 |
| paused | 地图运动、动作、转场停止；可继续恢复 |
| modal open | 暂停演出并禁用地图输入，关闭后保留原手动暂停状态 |
| ended | 仅整条当前故事的末节点结束，回目边界继续下一回 |
| error | 显示带节点 ID 的错误，不假装继续成功 |

继续和空格推进同一状态机，连点不能跳过未完成移动或重复写历史。自动播放等待本段动作与跨院转场完成；打开弹窗期间不推进。存档只保存稳定 reading/ended 节点，移动途中不存漂浮小数位置。刷新、段落选择直接进入目标局部场景，不重演一次不相干的全府旅行。

行动路线来自 `engine.movementPaths()` 的真实 A* 结果，而非用起终点虚构直线；动作光圈/路线不要遮挡地图姓名。尊重 prefers-reduced-motion，暂停时画面必须稳定；装饰动画不能继续抢注意力。

## 指针、缩放与可读性

- 地图右上缩放按钮桌面 44×44px、手机 40×40px；z-index 高于立绘，必须实际点到。
- 大幅透明立绘及其容器 pointer-events:none；在场姓名、人物切换按钮等明确控件才 pointer-events:auto，避免点放大却打开人物弹窗。
- 缩小时人物按脚底锚点保持约 48px 的可见高度；姓名约 12px、地点约 13px。逻辑坐标和寻路不能随显示缩放变化。
- 标签先错开，必要时隐藏次要冲突文字，优先保留讲话人/黛玉；不能让姓名缩成噪点或无节制堆叠。
- 拖动镜头后可用“回到剧情镜头”恢复跟随；拖动不误触角色，缩放不误触人物资料。
- 有 aria-label、可见焦点、键盘可操作按钮；不能只用颜色表达当前状态。

## 总览与行迹

浏览总览仅显示地点说明，不改变当前对白；只有明确定位按钮才跳剧情。府内顺序跨地点先显示沿合法道路的移动，再恢复局部场景；速度、暂停、跳过与主播放一致。转场属于展示，不改写局部坐标或剧情历史。雨村独立支线不安排黛玉走路。

外地、梦境、回忆按回目行迹组织，明确无距离比例，不能将跨城市行程伪装为院中步行。新回要设置适当的视图策略，现有 `<3` 判断只是前三回实现，参见新增回目流程。

## 人物资料和文案

设置聚合保存/读取/重玩、底本与改编说明、地点目录、人物图鉴。图鉴和资料用受检 faceBox 做头肩近景；对话继续使用完整立绘。不要复制同样的人物简介到导航、图鉴卡和对白上方多个位置。

来源说明记录当前回目、准确起句、改编标记、地图推定。梦境/回忆/转述徽标保留；制作技术参数不塞进普通剧情流程。新回上线同步修改写死的“前三回”等文案，不能让内容扩了而说明仍声称只三回。

## 视觉验收

至少检查 1440×900、1280×720、390×844。逐次切换高矮立绘、单人/多人、长短对白、行动/对白、地图/总览；地图容器不跳高，所有主控件一屏可用，正文不被立绘盖住，无横向页面溢出。总览内部有意滚动与整页横向溢出分开判断。

人物资料点击、图鉴近景和缩放按钮要实际操作；仅截图正常不能证明命中区域正确。长列表弹窗要内部滚动；对白别靠不断增加容器高度解决。已有 CSS 经多轮修订，修改前搜索选择器，优先整理对应规则，避免继续用无穷尾部覆盖掩盖冲突。
